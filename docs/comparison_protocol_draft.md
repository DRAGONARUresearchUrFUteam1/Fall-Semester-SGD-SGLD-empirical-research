# Протокол сравнения: черновик для ревью

**Статус:** техническая основа для первого пилота. Не утверждает гиперпараметры,
бюджеты, сравнения H1–H5 или готовность всех методов.

## Что уже определено

- Постановка и гипотезы: [решение в #3](https://github.com/DRAGONARUresearchUrFUteam1/Fall-Semester-SGD-SGLD-empirical-research/issues/3#issuecomment-6479411626).
- Для двух 2D-профилей из [артефакта #6](https://github.com/DRAGONARUresearchUrFUteam1/Fall-Semester-SGD-SGLD-empirical-research/issues/6/artifacts/1)
  фиксируем исходную область, границы и отдельные `geo`, `tan`, `good`.
  Первые обнаружения не сбрасываются после возврата; `good` без δ не оценивается.
- В исходной постановке сравнение ведётся при одинаковой стоимости
  компонентных градиентов/субградиентов, включая затраты калибровки. Храним
  раздельные счётчики `train`, `calibration`, `diagnostics`; включение диагностических
  градиентов в лимит ещё согласуется. Вызовы значений функции не конвертируются в градиенты.
- Цель для принятого семейства:
  \(F_c(u,v)=u^4/4-u^2/2+v^2/2+|v-cu^2|\), \(c\in\{0,1/4\}\).
  На изломе прототип использует субградиент с `sign(0)=0`. Для семейства с принятыми
  коэффициентами аналитические минимумы лежат на многообразии излома:
  при фиксированном \(u\) минимизатор по \(v\) — \(\min(cu^2,1)\);
  минимум соответствующего локального полинома достигается при
  \(u^2=1/(1+2c^2)\), где \(cu^2<1\). При \(cu^2>1\) для \(c=1/4\)
  редуцированная цель возрастает по \(u^2\).

## Пилот инфраструктуры

1. `configs/saddle_pilot.yaml` — **пример**, не научный выбор. Использует
   два компонента \(F_c(x)\pm s^\top x\) с общим средним \(F_c(x)\);
   мини-батчи выбираются равномерно без возвращения внутри шага.
   Это явно искусственный стохастический оракул, не модель шума будущих данных.
   `configs/saddle_pilot_paired.yaml` демонстрирует вариант C: несколько пар
   \(F_c(x)\pm s_j^\top x\). По каждой паре средняя цель остаётся \(F_c\).
   Список `directions` задаёт по одному вектору на пару; `slope` сохраняется
   только в старом двухкомпонентном конфиге. Оба профиля \(c\) доступны в C.
2. Базовые SGD/SGLD получают одну стартовую точку и парные seeds. Генераторы
   мини-батчей и добавленного гауссовского шума разделены. Вариант с \(T=0\)
   должен совпадать с SGD при тех же входах. Шаг и температура в пилоте постоянны.
3. `python -m src.train --config configs/saddle_pilot.yaml --plan` проверяет
   конфиг и показывает список пар метода и seed, **не производя обновлений**.
   Пример ограничивает число шагов, а не вводит общий оракульный бюджет.
4. При исполнении каждая пара получает отдельный UUID. Старые `config.json`
   и `metrics.jsonl` остаются совместимы с `src.results`; в v1 `escape_status`
   не перегружен тремя новыми событиями. В отдельном
   `saddle_measurements.jsonl` пишутся `state`, `transition`, `first_detection`
   и `termination`. Норма градиента перехода относится к **исходной**
   точке перехода, а не к новому состоянию.
   В конфиге запуска `oracle` фиксирует направления, размер популяции,
   выборку и аналитическую ковариацию среднего градиента данного батча
   (`known_by_design`, до масштабирования шагом). Полный батч действительно
   вычисляет все компоненты; аналитический эталон не расходует калибровочные вызовы.
5. Для проверок работоспособности достаточно тестов из `tests/test_backlog_foundations.py`.
   Нужные перед сравнительной серией проверки: штатное завершение, восстановление
   первого события из файлов, повтор с парным seed, сверка оракульного счётчика.
   Полноценная агрегация журнала, checkpoint/resume, визуализация траекторий и отдельный
   стабильный контракт запуска пока не сделаны. Техническое прерывание может оставить
   журнал без `termination`; такое отсутствие нельзя считать штатным завершением.

## Правила для обсуждения перед сравнительной серией

| Решение | Предложение для обсуждения | Что нужно от команды |
|---|---|---|
| Единая ось затрат | Лимит компонентных вычислений; не тратить остаток на шаг с иным batch size молча; сравнивать на заранее определённых бюджетных отметках | Включение диагностических градиентов, правила первых/последних точек, затраты HVP и калибровки |
| Сопоставимые условия | Парные начальные точки/данные и seed; отдельные RNG для обучения, добавки и измерений | Список seed, минимальное число повторов и состав задач |
| Настройка | Задать сетки до сравнения; на статистических задачах пользоваться validation для выбора параметров и test для финальной оценки | Шаги, температуры, размеры батчей, допустимые правила подбора |
| H2, H4: структура | Сверять covariance обновления, полную дисперсию и её долю в отрицательном подпространстве при общих состояниях; траекторные оценки показывать отдельно | Утверждённые формулы matching и инварианты многомерного семейства |
| H3: расписание | Сравнивать ожидаемую суммарную энергию добавки на общем горизонте; реализованную энергию сохранять отдельно | Расписания, способ подбора без использования test и допустимая потеря вероятности выхода |
| H5: перенос | Заморозить настройку, выбранную на исходном batch size; целевую перенастройку учитывать отдельно | Определение ρ, мера потери качества и выбор контрольного сравнения |
| Выход | Отдельные первые события и отчёт по причинам окончания всех попыток | Основной endpoint, δ, область D, приоритет неуспеха, возвраты, интервалы и цензурирование |

Полный набор функций и методы остаются за владельцами соответствующих карточек.
Не выводить проверку гипотез из пилота с шаговым лимитом или из unit-тестов.
