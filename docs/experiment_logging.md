# Логирование экспериментов (схема v1)

## Формат и структура

Выбран **JSONL**: одна JSON-запись на измеряемую итерацию. Можно дописывать
измерения и сохранять вложенные массивы параметров без неоднозначного CSV-кодирования.
Каждый вызов `ExperimentLogger` создаёт новый UUID v4 и отдельную папку:

```text
results/runs/<experiment_id>/
├── config.json      # версия схемы, ID, время UTC, полный снимок конфигурации
└── metrics.jsonl    # записи измерений, flush после каждой записи
```

Обычные результаты игнорируются Git. Синтетический пример для проверки формата
хранится в `docs/examples/logging/`; это **не экспериментальные данные**.
Внешние сервисы, аккаунты и доступ к сети для логирования не нужны.

## Использование

```python
from src.experiment_logging import ExperimentLogger

config = {
    "method": "SGD",
    "seed": 42,
    "learning_rate": 0.01,
    "batch_size": 32,
    "temperature": None,
    "task": {"name": "your_task"},
    "escape_rule": {"description": "Определяется протоколом задачи"},
}

with ExperimentLogger(config) as logger:
    logger.log(
        iteration=0,
        loss=1.5,
        gradient_norm=0.2,
        parameters={"x": [0.1, 0.2]},
        escape_status="not_escaped",
    )
    # При расписании сохраняем фактические значения текущей итерации.
    logger.log(
        iteration=10, loss=1.2, gradient_norm=0.1,
        parameters={"x": [0.2, 0.3]},
        learning_rate=0.005, temperature=0.0,
        escape_status="escaped",
    )
    print(logger.experiment_id, logger.run_dir)
```

Передавайте **полную разрешённую конфигурацию**, а не только путь к YAML:
включая задачу, параметры модели/оптимизатора, расписание, критерий выхода,
бюджет и при необходимости git commit. Логгер сохраняет переданные данные,
но не восстанавливает пропущенные настройки и не выставляет seed за обучение.
Для SGLD стоит явно записывать в конфиг соглашение о температуре и масштабировании
возмущения. Контекстный менеджер закрывает файл даже при ошибке обучения.

## Поля записи

| Поле | Смысл |
|---|---|
| `schema_version` | Версия формата, сейчас `1` |
| `experiment_id` | UUID запуска; объединяет метрики и конфигурацию |
| `method`, `seed` | Метод и seed из конфигурации |
| `learning_rate`, `batch_size`, `temperature` | Фактические значения на этой итерации; по умолчанию берутся из конфига |
| `iteration` | Целое неотрицательное число; строго возрастает, пропуски разрешены |
| `loss` | Значение целевой функции в документированной точке измерения |
| `gradient_norm` | Неотрицательная норма градиента/выбранного субградиента |
| `parameters` | Текущие оптимизируемые переменные/веса: массив, словарь, скаляр или `null` |
| `escape_status` | `not_evaluated`, `not_escaped` или `escaped` |
| `logged_at` | Время записи, UTC в ISO 8601 |

`temperature=null` означает «не применимо/не задано», `0` — явно нулевую
температуру. Отрицательные интенсивности и learning rate запрещены, нулевые
разрешены. `loss` и `gradient_norm` могут быть `null`, если измерение недоступно;
`NaN`/`Infinity` запрещены во всех JSON-данных. Это предотвращает невалидный JSON:
при расходимости вызывающий код должен явно обработать нечисловые значения.

Логгер не вычисляет норму, loss и факт выхода. Протокол должен определить,
когда измеряются loss/веса (до или после обновления), какую норму и какой
градиент используют, является ли статус выхода текущим или накопленным.
Сам по себе `escaped` не доказывает продуктивность выхода.

Поддержаны JSON-значения, `Path`, NumPy-массивы/скаляры и PyTorch-тензоры
(через `detach().cpu().tolist()`, без обязательного импорта torch).
Для больших моделей передавайте `parameters=None` на большинстве итераций,
а полные веса сохраняйте в checkpoints или логируйте редко; перенос тензора
с GPU и запись больших массивов имеют стоимость.

Один логгер — один процесс-писатель. Параллельные запуски используют разные
экземпляры и UUID. Продолжение записи в существующую папку не поддерживается;
перезапуск получает новый ID (при необходимости укажите `parent_experiment_id`
в конфиге). `flush()` обеспечивает видимость записи, но не заменяет `fsync()`
при сбое питания. Прерванная/повреждённая последняя строка считается ошибкой,
а не молча теряется при агрегации.

## Загрузка и автоматическая агрегация

Из корня репозитория, после установки зависимостей:

```bash
# Только синтетическая проверка интерфейса, не ML-эксперимент
python -m src.logging_example

# Собрать все запуски, включая вложенные папки, в одну таблицу
python -m src.results results/runs --output results/aggregated.csv

# Проверить сохранённый в репозитории пример
python -m src.results docs/examples/logging

python -m pytest tests/
```

```python
import json
import pandas as pd
from src.results import load_results

df = load_results("results/runs")
# Одна строка = одно измерение, а не один запуск.
counts = df.groupby(["experiment_id", "method", "seed"]).size()
final = df.sort_values("iteration").groupby("experiment_id").tail(1)

# Дополнительные настройки сохранены без потерь в словаре config.
configuration_columns = pd.json_normalize(df["config"]).add_prefix("config.")
wide = df.drop(columns="config").join(configuration_columns)

# При экспорте вложенные config и parameters кодируются JSON-строками.
from_csv = pd.read_csv("results/aggregated.csv", keep_default_na=False)
from_csv["config"] = from_csv["config"].map(json.loads)
from_csv["parameters"] = pd.Series(
    [json.loads(value) for value in from_csv["parameters"]], dtype=object
)
```

`load_results` принимает корень коллекции или одну папку запуска. Помимо
полей метрик возвращает `created_at`, полный `config` и `run_dir`.
Пустая коллекция/запуск без измерений дают пустую таблицу с той же схемой.
Отсутствующая папка, несовместимая версия, повторяющиеся ID, неверный порядок
итераций, несовпадение метода/seed/ID с конфигом или повреждённые файлы вызывают
ошибку с путём (для метрик также номером строки), чтобы не исказить выборку.
Агрегация не проверяет научную сопоставимость протоколов и бюджетов: это задача
экспериментального дизайна, а не формата хранения.
